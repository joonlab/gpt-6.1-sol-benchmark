# tools 트랙: function calling · 에이전트 루프 · JSON 구조화 출력

측정일 2026-09-30. 실행 환경은 ChatGPT Pro 구독의 Codex 환경이다.

## 무엇을 테스트했나

gpt-6.1-sol 이 도구를 제대로 쓰는지를 세 갈래로 봤다.

1. **function calling**: 질문을 주고, 필요한 툴을 맞는 인자로 부르는지, 툴이 필요 없는 질문에서는 부르지 않는지.
2. **에이전트 루프**: 툴을 3~5번 이어 불러야 풀리는 과제를 끝까지 풀어 정답을 내는지.
3. **JSON 구조화 출력**: 주어진 JSON Schema 에 맞는 JSON 을 내는지, 값이 맞는지. 스키마를 프롬프트로만 준 경우(prompt)와 API 로 강제한 경우(strict)를 나눴다.

툴은 날씨·환율·일정·DB·계산기 5종의 가짜 툴이고, 고정 데이터로만 답한다. 스키마와 데이터는 [tools.md](tools.md) 에 있다. 시나리오·JSON 케이스에 나오는 인명은 모두 가공 예시다.

## 방법

| 파트 | 규모 | 채점 |
|---|---|---|
| 기본 function calling | 20 시나리오(툴 필요 15, 불필요 5) × 5모델 × N=2 | 에피소드(최대 6턴)에서 나온 호출 집합을 기대 호출과 대조 |
| 어려운 function calling | 10 시나리오 × 5모델 × N=2 | 위와 같음. 조건부 호출, 상대 날짜, 연쇄 의존, 이름→ID 조인, 삭제 요청(호출 0 기대), 단위 암시 |
| 에이전트 루프 | 8 과제 × 5모델 × N=2 | 최대 12턴. 마지막 줄 `최종 답:` 뒤 값을 정답과 대조 |
| JSON 출력 | 15 케이스 × 2모드 × 5모델 × N=2 | JSON Schema(Draft 2020-12) 검증 + 정답 필드 대조 |

- 모델: gpt-6.1-sol(대상), gpt-6-sol, gpt-6-astra, gpt-6-luna, gpt-5.6-sol.
- reasoning effort: 지정하지 않았다(모델 기본값). 툴 턴의 reasoning 토큰은 대부분 0이었다.
- 채점은 전부 결정론이다. LLM 판정은 쓰지 않았다.
  - 인자 대조: 도시명 별칭 통일, 통화코드 대문자, 날짜 정확 일치, 계산식은 계산한 값으로, SQL 은 실제로 실행한 결과로 비교했다.
  - **strict**: 기대 호출이 전부 맞고 여분 호출이 0. 툴이 필요 없는 질문에서 한 번이라도 부르면 오답. **lenient**: 여분 호출은 허용.
  - 에이전트 정답: 숫자는 상대오차 1% 또는 절대 0.05 이내, 문자열은 별칭 중 하나가 들어 있으면 정답.
  - JSON: 원문 그대로 파싱(parse_raw), 스키마 통과(schema_valid), 정답 필드 일치(value_ok). j08(레시피)은 정답이 없어 스키마만 본다.
- 사용한 호출 수: function calling 400턴, 어려운 function calling 200턴, 에이전트 386턴, JSON 300회.

## 결과

### 정확도 (전부 N=2)

| 모델 | 기본 FC strict | 어려운 FC strict | 불필요 호출 회피 | 에이전트 8과제 | JSON prompt 스키마 / 값 | JSON strict 스키마 / 값 |
|---|---|---|---|---|---|---|
| **gpt-6.1-sol** | 40/40 | 20/20 | 10/10 | 16/16 | 100% / 100% | 100% / 100% |
| gpt-6-sol | 40/40 | 20/20 | 10/10 | 16/16 | 100% / 100% | 100% / 100% |
| gpt-6-astra | 40/40 | 20/20 | 10/10 | 16/16 | 100% / 100% | 100% / 100% |
| gpt-6-luna | 40/40 | 20/20 | 10/10 | 16/16 | 100% / 96.4% (27/28) | 100% / 100% |
| gpt-5.6-sol | 40/40 | 20/20 | 10/10 | 16/16 | 100% / 100% | 100% / 100% (끊긴 3건 제외) |

- 여분 호출은 모든 모델·모든 시나리오에서 0이었다. API 오류도 function calling·에이전트에서는 0건이다.
- JSON strict 의 j07 은 모든 모델에서 HTTP 400 `invalid_json_schema` 로 거부됐다. strict 모드가 `uniqueItems` 키워드를 허용하지 않아서다. 모델 응답이 없으므로 분모에서 뺐다(strict 유효 28건, gpt-5.6-sol 은 아래 끊김 3건을 더 빼 25건).
- **끊긴 스트림 처리**: gpt-5.6-sol strict 모드 3건(j12 1건, j13 2건)은 완료 신호와 usage 없이 약 72초 만에 끊겼다. 모델 오답이 아니라 관측 불가로 보고 채점 분모와 지연 집계에서 뺐다. function calling·에이전트 기록에는 끊긴 턴이 없었다.
- gpt-6-luna 의 prompt 모드 오답 1건은 j03(영수증) 합계다. 정답 17,300 대신 15,800 을 냈다. 같은 케이스의 나머지 3회는 맞았다. 1건 차이라 모델 간 차이로 보지 않는다.
- prompt 모드에서도 5개 모델 모두 응답 원문이 그대로 JSON 으로 파싱됐다(코드펜스 없음).

| 모델 | 툴 호출 수 중앙값 | 모델 턴 중앙값 | 툴 오류 합계 | reasoning 토큰 중앙값 |
|---|---|---|---|---|
| **gpt-6.1-sol** | 3 | 4 | 0 | 0 |
| gpt-6-sol | 3 | 4 | 1 | 0 |
| gpt-6-astra | 3 | 4 | 0 | 0 |
| gpt-6-luna | 3.5 | 4.5 | 2 | 0 |
| gpt-5.6-sol | 3 | 4 | 1 | 19 |

툴 오류 4건은 모두 a6 과제에서 계산기가 지원하지 않는 식을 보낸 경우다. 네 에피소드 모두 오류를 받은 뒤 식을 고쳐 계산기를 다시 불렀고 정답을 냈다. 0~2건 차이라 구분 불가다.

| 모델 | 툴 턴 중앙값 | 툴 턴 p90 | 에이전트 에피소드 중앙값 | JSON strict 호출 중앙값 |
|---|---|---|---|---|
| **gpt-6.1-sol** | 3.38s | 4.82s | 15.4s | 3.87s |
| gpt-6-sol | 2.55s | 3.79s | 12.4s | 2.88s |

이 트랙은 모델별로 블록을 이어 붙여 순서대로 실행했다(한 모델의 작업을 다 끝내고 다음 모델로). 셔플이나 짝짓기를 하지 않았고, 같은 시간에 다른 트랙도 돌고 있었다. 그래서 위 지연에는 시간대별 서버 부하와 모델 차이가 섞여 있다. **모델 간 속도 순위의 근거로 쓰지 않는다.** 속도 비교는 셔플해서 잰 speed 트랙을 본다.

## gpt-6.1-sol 관찰

관측:

- 기본 20, 어려운 10 시나리오, 에이전트 8과제를 N=2 전부 맞혔다. 툴이 필요 없는 질문(기본 세트 5개, 어려운 세트의 삭제 요청 h05 와 "지금 몇 시야?" h09)에서는 한 번도 툴을 부르지 않았다.
- 조건부 호출(h01: 서울이 20도를 넘을 때만 부산 조회)에서 서울 18도를 보고 부산은 조회하지 않았다.
- 상대 날짜("다음 주 월요일", "이번 주 금요일", "다음 달 첫째 날")를 지시문의 기준일에서 정확히 계산했다.
- 에이전트 과제에서 툴 오류가 0건이었다.
- JSON 은 두 모드 모두 스키마 통과율·값 정답률 100%였다. 지시 주입이 섞인 j14 에서도 JSON 을 유지했다.

해석:

- 이 난이도에서는 정확도로 gpt-6.1-sol 과 비교군을 가를 수 없다. 5개 모델이 모두 천장에 붙었다.
- 툴 오류 0건은 비교군(0~2건)과 1~2건 차이라 구분 불가다.

## 한계

- 과제가 쉬워서 천장 효과가 났다. 툴 20개 이상, 모호한 인자, 툴 오류 복구, 긴 호출 체인이 들어간 세트가 있어야 변별된다.
- 반복이 N=2라 분산 추정이 거칠다.
- ChatGPT Pro 구독의 Codex 환경에서 잰 값이라, 공개 API 에서의 동작과 다를 수 있다.
- 기본 세트 s03 은 처음에 "내 일정"으로 물었다가 주체가 모호해 모델이 되묻는 바람에 "사내 일정 전체"로 문구를 고쳐 다시 돌렸다. 결과 파일에는 고친 문구의 기록만 들어 있다.
- 지연은 모델별 블록 순서로 실행했고 다른 트랙과 동시에 쟀다(위 지연 절 참고).
- JSON 케이스 j01·j05 원문에는 예시 이메일 주소가 들어 있었다. 공개본에서는 `[예시 이메일]` 로 가렸다.

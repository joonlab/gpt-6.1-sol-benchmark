# vision_ko — 비전 17과제 + 한국어 지시 준수 16과제

gpt-6.1-sol 이 이미지를 얼마나 정확히 읽는지, 그리고 한국어로 쓴 형식 제약(문장 수, 글자 수, 존댓말/반말, 금지어 등)을 얼마나 지키는지 쟀습니다.
비교군은 gpt-6-sol · gpt-6-astra · gpt-6-luna · gpt-5.6-sol 이고, 측정일은 2026-09-30 입니다.

## 요약

- 330회 호출 모두 완료, 실패 0건. 비전 170셀(17과제 × 5모델 × 2회), 한국어 160셀(16과제 × 5모델 × 2회).
- gpt-6.1-sol 은 66셀 전부 만점이었습니다(비전 34/34 전 필드 정답, 한국어 32/32 전 제약 통과). gpt-6-astra 도 66/66 입니다.
- 다만 이 트랙은 천장에 걸렸습니다. 330셀 중 만점이 아닌 셀은 7개뿐이고 모델 간 차이는 0~4셀입니다. 상위 4개 모델(6.1-sol · astra · 5.6-sol · 6-sol)은 이 데이터로 구분할 수 없습니다.
- 반복해서 나온 오답은 gpt-6-luna 의 90도 회전 텍스트(2회 모두 `ORDER 58213-X`, 정답 `ORDER 58213-ZX`) 하나입니다.

## 1. 무엇을 테스트했나

### 1-1. 비전 17과제

정답을 미리 아는 합성 이미지 17장을 만들어(seed 고정) 모델에게 보여 주고, 답을 JSON 으로 받았습니다. 이미지는 [`images/`](images/) 에 있습니다.

| count | 3 | `scatter_quadrant` 사분면별 점 수(6/4/3/5) · `count_circles` 원 23개 · `count_shapes` 원 6 · 사각형 8 · 삼각형 5 |

표 이미지(`table_ocr`)에 들어간 이름은 모두 가상 인물입니다.

## 2. 방법

| 항목 | 값 |
|---|---|
| 실행 환경 | ChatGPT Pro 구독의 Codex 환경 |
| 모델 | gpt-6.1-sol, gpt-6-sol, gpt-6-astra, gpt-6-luna, gpt-5.6-sol |
| reasoning effort | 지정하지 않음(환경 기본값) |
| 반복 N | 과제당 모델당 2회 |
| 호출 수 | 330 (비전 170 + 한국어 160), 실패 0 |
| 동시 요청 | 3 |
| 투입 순서 | 회차 → 과제 → 모델 순. 한 과제의 다섯 모델이 연달아 들어가고, 과제마다 gpt-6.1-sol 이 늘 첫 번째 |
| 이미지 전송 | PNG 를 base64 data URL 로 인코딩해 입력 |
| 시간 측정 | 클라이언트 벽시계. 총시간과 첫 텍스트 도착까지(TTFT) |

채점은 모두 규칙 기반이고 LLM 판정은 쓰지 않았습니다.

- **비전**: 응답에서 첫 JSON 객체를 뽑아 필드별로 판정합니다. 수치(`num`)는 허용오차 안이면 정답, 정수(`int`)는 정확일치, 문자열(`str`)은 공백·대소문자를 무시한 정확일치(공백을 전부 지운 뒤 비교), 집합(`set`)은 순서 무관 일치, 목록(`list`)은 순서 포함 일치, 한글 문단(`text`)은 `1 − 편집거리/정답길이` 부분점수입니다. 과제 점수는 필드 평균, `all_correct` 는 전 필드 만점입니다.
- **한국어**: 제약마다 정규식·개수 판정을 합니다. 과제 점수는 통과한 제약 비율, `strict` 는 전 제약 통과입니다.
- 응답 스트림이 도중에 끊긴 기록(usage 없음)은 집계에서 빼는 규칙이었지만, 이 트랙은 330건 모두 usage 가 있어 뺀 기록이 없습니다.

## 4. gpt-6.1-sol 관찰

관측
- 비전 34셀, 한국어 32셀 모두 만점이었습니다. JSON 파싱 실패도 0건입니다.
- 추론토큰 중앙값은 두 파트 모두 0, 비전 출력토큰 중앙값은 43 으로 적은 편이었습니다.
- 그런데 총시간 중앙값은 비전 4.65초, 한국어 6.09초로 두 파트 모두 다섯 모델 중 가장 길었습니다.

해석
- 6.1-sol 이 이 과제들에서 틀리지 않았다는 것까지가 이 데이터로 말할 수 있는 범위입니다. astra 도 똑같이 66/66 이고, 5.6-sol(65/66)·6-sol(64/66)과는 1~2셀 차이라 "비전이나 한국어 지시 준수가 더 낫다"는 결론은 낼 수 없습니다.
- 속도가 가장 느렸다는 점은 speed 트랙의 "가시 스트리밍 속도가 느린 편"과 같은 방향입니다. 다만 투입 순서상 6.1-sol 이 과제마다 늘 첫 번째로 들어갔고, 부하 조건이 다른 두 시간대가 섞여 있어(6절) 참고값으로만 봅니다.
- `korean_ocr` 의 비쳐→비춰 치환은 세 번 모두 같은 단어, 같은 방향이었습니다. 판독 실패라기보다 모델이 더 흔하다고 여기는 표현으로 바꿔 쓴 것으로 보입니다(추정, 검증 안 함). 원문 그대로 옮겨야 하는 OCR 이라면 후검증이 필요하다는 신호로 읽습니다.
- luna 의 `rotated_90` 은 같은 방향으로 두 번 틀려 우연보다는 실제 약점일 수 있지만, 과제 1개 · N=2 라 일반화하지 않습니다.

## 5. 채점 수정 이력

### «꼽힘» 오판 수정 (2026-09-30, 점수가 바뀐 수정)

- **무엇이 틀렸나.** `three_line_summary` 의 명사형 종결 판정은 줄 끝 어미를 `함·음·됨·임·짐·님·름·늠·봄·춤·옴` 목록으로만 받았습니다. 그래서 gpt-6-sol 1회차 셋째 줄 "…환율이 변수로 **꼽힘**"이 실패로 잡혔습니다. "꼽힘"은 올바른 명사형 종결이라 채점기 오판입니다.
- **어떻게 고쳤나.** 어미 목록 대신 마지막 음절의 받침이 ㅁ 또는 ㄻ 인지 봅니다. "봄"처럼 ㅁ 받침으로 끝나는 일반 명사도 통과하는데, 명사로 끝나는 줄도 명사형 요약으로 볼 수 있어 그대로 두었습니다.
- **재채점.** 모델을 다시 호출하지 않고 저장된 응답만 새 판정으로 다시 채점했습니다. 수정 전 판정으로 330건을 다시 돌리면 저장된 판정과 전부 일치했고, 수정 후에는 정확히 이 1셀만 바뀌었습니다. `three_line_summary` 10건의 마지막 음절은 함·됨·임·힘뿐이었습니다.

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| gpt-6-sol 한국어 strict | 31/32 | 32/32 |
| gpt-6-sol 한국어 평균 점수 | 0.992 | 1.000 |
| gpt-6-sol 합계 만점 셀 | 63/66 | 64/66 |
| 330셀 중 만점 셀 | 322 | 323 |
| 전 모델 1.00 인 제약 | 46/48 | 47/48 |

6.1-sol · astra · luna · 5.6-sol 의 수치와 순위는 바뀌지 않았습니다. 이 레포의 CSV 는 모두 수정 후 판정이고, 바뀐 셀은 `ko_results.csv` 의 `regraded=True` 로 표시했습니다.

### 검토했지만 적용하지 않은 것

- **문자열 비교의 공백 무시.** gpt-6-sol `rotated_90` 0회차 답은 `ORDER58213-ZX` 로 ORDER 와 숫자 사이 공백이 빠졌습니다(이미지에는 공백 있음). 채점 규칙이 공백을 지우고 비교하므로 정답 처리됐습니다. 공백까지 엄격하게 보면 이 셀은 0.0 이 되어 6-sol 비전 전 필드 정답이 32/34 에서 31/34 가 됩니다. 실행 전에 정한 규칙이라 데이터를 본 뒤 바꾸지 않았습니다. 1건 차이라 구분 불가이고 순서도 바뀌지 않습니다. 이 셀은 `vision_results.csv` 의 `text_diff_vs_gold` 에 `' ' -> ''` 로 남아 있습니다.
- **`korean_ocr` 편집거리의 공백 무시.** 띄어쓰기 오류는 감점되지 않습니다. 이번 10건 중 7건은 정답과 바이트 단위로 같았고, 나머지 3건은 비쳐→비춰 한 글자 차이라 영향이 없었습니다.

### 이번 데이터에는 영향이 없었던 잠재 오판 위험

이번 330건에는 해당 사례가 없어 점수에 영향이 없었습니다. 같은 과제를 다시 돌린다면 손볼 후보입니다.

- 수치 필드에 `"23~24"` 같은 문자열이 오면 첫 숫자만 읽어 통과시킬 수 있습니다.
- 전각 영문(`ＯＲＤＥＲ`)이나 en dash(`–`)가 섞이면 0점이 됩니다.
- `line_points.max_month` 정답이 문자열 `"7월"` 이라 숫자 `7` 로만 답하면 0점입니다.
- 글자 수 기준이 과제마다 다릅니다. `numbered_list`(20자)·`three_line_summary`(40자)는 프롬프트에 "공백 포함"이 없는데 공백을 넣어 셉니다. 이번 20건은 더 엄격한 기준으로도 전부 통과했습니다.
- 문장 분리는 `[.!?]` 뒤 공백 기준이라 `다.그리고` 처럼 공백이 없으면 두 문장을 하나로 셉니다. 종결부호 개수로 따로 센 값과 대조했을 때 문장 수를 채점하는 70건은 모두 일치했습니다.
- `no_AI` 는 `에이아이`·전각 `ＡＩ` 를 잡지 못하고, 이모지 판정 범위에서 ⭐ 같은 일부 이모지가 빠집니다. 해당 과제 20건 응답에는 이런 사례가 없었습니다.

## 6. 한계

- **effort 미지정.** 환경 기본값으로 돌렸고, 그 기본값이 모델마다 같은지는 관측할 수 없습니다. 6.1-sol · astra 의 추론토큰 중앙값 0 은 그 기본값에서의 값입니다.
- **N=2.** 1~2건 차이는 구분 불가입니다.
- **천장 효과.** 330셀 중 323셀이 만점입니다. 깨끗하게 렌더링한 합성 이미지와 짧은 형식 제약이라 난도가 낮았습니다. 실사 사진, 스캔 문서, 손글씨, 긴 한국어 글의 자연스러움은 재지 않았습니다.
- **실행이 두 시간대로 나뉨.** 1차 실행은 47회(08:28:53~08:29:52, 다른 트랙과 동시 실행 중)에서 멈췄고, 나머지 283회는 10:35:06~10:43:25 에 다른 트랙이 끝난 뒤 재개해 돌렸습니다. 지연 값에는 부하 조건이 다른 두 묶음이 섞여 있습니다(예: astra 비전 총시간 중앙값이 앞 묶음 2.98초, 재개분 4.52초). 정확도에는 영향이 없다고 보지만(추정), 지연 비교는 참고값입니다.
- **판정기 근사.** 문장 분리, 존댓말, 명사형 종결은 정규식·받침 판정 근사입니다.
- **지연은 벽시계.** 동시 요청 3, 구독 환경 경유 측정이라 공식 API 지연과 다를 수 있습니다.

### `vision_tasks.csv`

|---|---|

| 컬럼 | 뜻 |

# 롱 컨텍스트 (longctx)

측정일 2026-09-30 · 대상 `gpt-6.1-sol` · 비교 `gpt-6-sol`, `gpt-6-astra` · 실행 환경: ChatGPT Pro 구독의 Codex 환경

## 무엇을 테스트했나

1. **입력 한도**: 이 환경에서 gpt-6.1-sol 이 받아주는 입력 토큰의 정확한 상한은 얼마인가.
2. **긴 문서 속 한 줄 찾기(NIAH)**: 16K부터 상한 직전(약 915K)까지, 문서의 앞·중간·끝 어디에 숨긴 문장이든 찾아내는가.
3. **여러 곳을 동시에 써야 하는 과제**: 5개 동시 회수(멀티니들), 흩어진 숫자 20개의 합계, 방해 메모와 "코드 갱신"이 섞인 최신값 추적(하드 NIAH).
4. **지연**: 같은 600K 입력에서 세 모델의 응답 시간을 번갈아 호출해 비교.

## 방법

| 실험 | 모델 | 길이 | effort | N |
|---|---|---|---|---|
| 단일 NIAH 사다리 (depth 0/25/50/75/100%) | 6.1-sol | 16·64·128·200·256K | low | 셀당 3 (75회) |
| 〃 | 6.1-sol | 400·600·850·915K | low | 셀당 1 (20회) + 초기 탐침 3회 |
| 〃 비교 | 6-sol, astra | 128·256·915K | low | 셀당 1 (모델당 15회) |
| 입력 한도 탐색 (거친 탐침 → 이분 → 토큰 단위 정밀) | 3종 | 272K~1.3M | low | 6.1-sol 36회, 비교군 각 3회 |
| 멀티니들 5개 + 숫자 20개 합계 | 3종 | 128K (N=3), 900K (N=2) | medium | 과제·모델별 |
| 〃 | 6.1-sol | 400K (N=3, 유효 2) | medium | |
| 하드 NIAH (방해 메모 60개 + 갱신) | 3종 | 128K (N=3), 850K (N=2) | low | |
| 지연 비교 (라운드로빈 순차) | 3종 | 600K | low | 모델당 3 |

총 228회 호출(6.1-sol 156 · 6-sol 36 · astra 36). 그중 한도 초과 거부 21회, 끊긴 스트림 2회. 228회에는 길이 보정용 16K 호출 1회(6.1-sol)가 포함되며, 이 1회는 CSV 에 넣지 않았다. `niah.csv` 의 `coarse_probe` 3행은 `limit.csv` 의 수락된 `coarse_probe` 행과 같은 호출이라 두 파일에 중복으로 들어 있다(CSV 행 합계 230 − 중복 3 + 보정 1 = 228).

- **필러 텍스트**: 숫자가 하나도 없는 한/영 혼합 무작위 문장을 12문장씩 문단으로 이어 붙였다. 그래서 문서 안의 숫자는 needle 과 합계용 장부 값뿐이다. 호출마다 seed 를 바꿔 문서가 매번 다르고, 전 호출에서 캐시 적중 토큰은 0이었다.
- **길이 맞추기**: 사전 보정으로 얻은 "약 3.07 문자/토큰"으로 문자 수를 정했다. 실제 입력 토큰은 서버가 돌려준 usage 값을 기록했다. 한도 정밀 탐색에서는 o200k_base 토크나이저로 토큰 수를 직접 맞췄고, 수락된 호출은 전부 "토크나이저 계수 + 6"이 서버 usage 와 정확히 일치했다.
- **needle 문자열**: `[메모] 금고 ORCHID-42 의 비밀 접근 코드는 12345-AB 이다.` 형태(금고 이름·코드는 호출마다 무작위, 한/영 병기). 질문은 항상 문서 **뒤**에 붙였다.
- **멀티니들**: 서로 다른 금고 5개를 depth 10/30/50/70/90% 에 넣고 5개 코드를 모두 답하게 했다.
- **합계**: 문서 곳곳에 장부 항목 20개(각 세 자리 정수)를 흩어 넣고 총합을 물었다.
- **하드 NIAH**: 비슷한 형식의 방해 코드 60개, 같은 금고의 옛 코드, 그 뒤쪽에 "코드가 갱신되었다"는 새 코드를 넣고 현재 코드를 물었다.
- **채점은 전부 결정론**이다. 정답 코드 문자열 포함 여부 / `금고명: 코드` 정규식 / `총합: N` 정수 일치 / 하드 NIAH 는 응답에 든 코드가 갱신값·옛값·방해값 중 무엇인지 분류. LLM 채점은 쓰지 않았다.
- **끊긴 스트림 처리**: 400K 과제의 rep 0 두 건(멀티니들 1, 합계 1)은 약 75초 뒤 텍스트와 usage 없이 스트림이 끝났다. 원본 집계와 같게 이 두 건은 채점에서 빼고(`valid=false`) 다시 호출하지 않았다. 그래서 400K 과제는 유효 N=2 다.

## gpt-6.1-sol 관찰

**관측**
- 입력 상한은 921,858 토큰이고, 비교한 두 모델과 같은 값이다.
- 상한 직전(약 914K)까지 단일 NIAH 98/98, 멀티니들·합계·하드 NIAH 유효 호출 전부 정답이었다.
- 600K 번갈아 호출에서 총시간 중앙값은 6.1-sol 12.95초, 6-sol 14.37초, astra 19.52초.
- 입력 16K → 850K 에서 총시간 중앙값이 2.5초 → 17.1초로 늘었다. 출력이 짧아 총시간 대부분이 TTFT(prefill)다.

**해석**
- 회수 정확도로는 세 모델이 구분되지 않는다. 단일·멀티 NIAH 와 하드 NIAH 는 셋 다 천장이다.
- 합계 과제에서 6.1-sol 은 7/7, 비교군은 각 1건씩 틀렸지만 N 이 2~3 이고 차이가 1건이라 **구분 불가**다.
- 속도는 6.1-sol 과 6-sol 의 범위가 겹쳐 같은 급으로 본다. astra 는 세 라운드 모두 가장 느렸고, 중앙값 기준 약 1.5배(라운드별 1.2~1.6배)였다.
- 921,858 이 1,050,000 − 128,000 = 922,000 과 142 토큰 차이라는 점에서 "공식 1.05M 에서 최대 출력분을 뺀 값"일 가능성이 있지만, 검증하지 않은 추측이다.

## 한계

- 반복 수가 작다. 400K 이상 NIAH 는 셀당 1회, 900K 과제는 2회다. 100% 는 "이 N 에서 실패가 없었다"는 뜻이지 실패율 0 의 증명이 아니다.
- 필러가 템플릿 문장이라 실제 문서보다 needle 이 눈에 띄기 쉽다. 비정형 실문서에서는 더 어려울 수 있다.
- 다른 트랙 실험과 같은 시간에 돌았다. 지연 절대값은 그날의 부하에 따라 달라진다.
- 입력 상한은 ChatGPT Pro 구독의 Codex 환경에서 관측한 값이다. 공개 API 의 한도와 다를 수 있다.
- 끊긴 스트림 2건의 원인은 확인하지 못했다.

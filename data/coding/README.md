# 코딩 트랙 — 명세만 보고 한 번에 맞는 Python 코드를 내는가

측정일 2026-09-30. 대상 gpt-6.1-sol, 비교군 gpt-6-sol · gpt-6-astra · gpt-6-luna · gpt-5.6-sol.
실행 환경은 ChatGPT Pro 구독의 Codex 환경이다.

## 요약

- gpt-6.1-sol 은 29과제 × 2회 = **58샘플 전부 통과(58/58)** 했다.
- 교과서형 19과제(core19)는 5개 모델 모두 38/38 로 만점이었다. 이 수준에서는 모델 간 차이가 보이지 않는다.
- 명세 조항이 많은 10과제(extreme10)에서 gpt-6-luna(14/20)와 gpt-6-sol(19/20)만 떨어졌고, gpt-6.1-sol · gpt-6-astra · gpt-5.6-sol 은 20/20 이었다.
- 만점 3개 모델은 이 과제 세트로 정확도 순위를 매길 수 없다. 차이는 토큰에서 났다: extreme10 추론 토큰 평균 astra 183 · 6.1-sol 353 · 6-sol 680 · 5.6-sol 1,330.
- gpt-6.1-sol 은 effort low 에서도 20/20 이었다.

## 1. 무엇을 테스트했나

모델에게 과제 명세만 주고(테스트는 비공개) 응답 코드 하나를 숨김 테스트로 채점했다.

| 단계 | 내용 | 숨김 테스트 | 샘플 |
|---|---|---|---|
| core19 | 쉬움 5 · 중간 8 · 어려움 6. 문자열 · 자료구조 · DP · 그래프 · 파서 · 시뮬레이션, 버그 수정 3과제 포함 | 193 | 5모델 × 19 × 2 = 190 |
| extreme10 | core19 가 전원 만점이라 추가한 과제. 명세 세부조항(에러 우선순위, 형식 엄격성, 경계 의미)과 입력 크기 제약을 함께 건다 | 118 | 5모델 × 10 × 2 = 100 |
| 수리 루프 | 첫 시도에서 실패한 샘플에 실패 테스트와 에러를 알려 주고 1회 고치게 함 | 같은 테스트 | 42 |
| effort 스윕 | extreme10 에서 gpt-6.1-sol low · high · xhigh, gpt-6-luna high | 같은 테스트 | 80 |

extreme10 과제: `re` 없이 만드는 정규식 엔진, POSIX식 셸 토크나이저(`shlex` 금지), 실행 전에 프로그램을 검증하는 어셈블리 인터프리터, 서로 다른 회문 부분수열 개수, 동아시아 문자폭을 고려한 표 포매터, 엄격한 날짜 형식의 영업일 계산, n=200,000 슬라이딩 중앙값, 표준형만 받는 로마숫자 파서, 순환 참조와 에러 우선순위가 있는 스프레드시트 평가기, O(1) LFU 캐시.

과제 명세 원문은 `tasks.csv` 의 `spec` 열에 있다. 숨김 테스트와 정답 구현은 공개하지 않는다.

## 2. 방법

- **모델·effort**: 5개 모델, reasoning effort `medium`. 과제당 독립 2회(N=2).
- **지시문**(모든 호출 공통): "You are an expert Python 3.12 programmer. Reply with exactly ONE \`\`\`python fenced code block containing the complete solution (including any imports). No explanation, no tests, no example usage, no print/input. Use only the Python standard library."
- **코드 추출**: 응답에서 가장 긴 python 코드 블록. 5개 모델 모두 290/290 에서 코드 블록 형식을 지켰다.
- **채점**: 별도 Python 프로세스에서 실행(프로세스당 10초, 테스트당 3초 제한). 채점은 전부 결정론적(정답 대조 · 예외 타입 확인)이고 LLM 판정은 쓰지 않았다.
  - **pass@1** = 숨김 테스트 전부 통과 + 금지 구문 미사용. 금지 구문은 `h1_expr`(eval/exec/compile/ast), `h2_json`(json/eval/ast), `x1_regex`(re), `x2_shell_split`(shlex) 네 과제에만 있고, 정규식으로 검출했다. 전체 370샘플에서 금지 구문 위반은 0건이었다.
  - **partial** = 샘플별 통과 테스트 비율의 평균.
  - 신뢰구간은 Wilson 95%.
- **테스트 검증**: 정답 구현이 311/311 을 통과하는지, 버그 수정 과제의 원래 코드와 순진한 구현(O(nk) 중앙값, 비표준형을 받아 주는 로마숫자 파서)이 실제로 떨어지는지 먼저 확인했다.
- **테스트 수정 1건**: 정규식 과제의 성능 테스트가 처음엔 `"x"*5000` 이었는데, 명세는 "다항시간"만 요구했으므로 O(n²) 풀이도 명세상 정답이다. 4개 모델이 이 테스트 하나에서만 시간초과해서 테스트가 부당하다고 판단하고 `"x"*200` 으로 바꿨다. 저장된 코드를 모델 재호출 없이 다시 채점했고, 이 폴더의 수치는 수정 후 채점이다.
- **수리 루프**: 실패 테스트 최대 6개의 식과 에러 메시지를 피드백으로 주고 1회 다시 풀게 했다. 같은 실패 샘플에 2회(trial 0, 1) 시도했다. gpt-6.1-sol 은 실패가 없어 자기 수리를 관측할 수 없었으므로, 대신 다른 모델의 실패 코드 7건을 gpt-6.1-sol 에게 고치게 했다(교차 수리). 기준선으로 gpt-6-astra 에게도 같은 7건을 줬다.
- **끊긴 응답 처리**: 생성 호출 374건 중 4건이 완료 신호 없이 끊겼다(사용량 기록 없음). 이 4건은 채점에서 제외하고 같은 조건의 재시도 결과를 썼다(medium 3건은 모두 `x9_spreadsheet` rep 0, 나머지 1건은 gpt-6.1-sol xhigh `x1_regex` rep 1).

## 4. gpt-6.1-sol 관찰

관측
- 첫 시도 58/58, effort low~xhigh 네 구간 모두 extreme10 20/20. 이 트랙에서 gpt-6.1-sol 이 틀린 샘플은 하나도 없었다.
- 다른 모델이 틀린 코드 7건(각 2회, 14시도)을 넘겨받아 14건 모두 전부 통과로 고쳤다. astra 도 14/14 로 같았다.
- 같은 정답률에서 extreme10 추론 토큰은 gpt-6-sol 의 약 절반, gpt-5.6-sol 의 약 1/4, gpt-6-astra 의 약 2배였다.
- effort 를 medium 에서 xhigh 로 올리면 추론 토큰이 9.3배, 지연 중앙값이 2.3배가 됐고 정확도 차이는 관측되지 않았다(이미 만점). low 는 medium 대비 추론 토큰이 약 1/3 이었다.

해석(검증하지 않은 추론)
- 정확도만 보면 이 과제 세트에서 gpt-6.1-sol · gpt-6-astra · gpt-5.6-sol 은 구분 불가다. "astra 에 가까운 수준"이라는 말은 이 트랙 정확도 기준으로는 맞지만, 토큰 효율은 astra 가 앞섰다.
- extreme10 에서 gpt-6.1-sol 의 지연이 astra 보다 길게 나온 것(26.4초 vs 20.0초)이 모델 속도 차이인지, 같은 시간대에 돌던 다른 트랙 부하 때문인지는 이 데이터로 분리할 수 없다.
- 이 과제 수준에서 코드를 뽑는 용도라면 effort low 로 충분했다. 더 어려운 과제에서도 그런지는 확인하지 않았다.

## 5. 한계

- 과제 29개, 모델·effort 조합당 N=2 라 신뢰구간이 넓다. 1~2샘플 차이는 구분 불가로 봐야 한다. gpt-6-sol 의 57/58 과 만점 모델들의 58/58 도 신뢰구간이 겹친다.
- 과제 대부분이 학습 데이터에 있을 법한 고전 문제의 변형이다. 새로운 문제 해결력보다 명세 준수와 경계 처리를 잰다.
- extreme10 은 core19 결과(전원 만점)를 본 뒤에 설계했다. 다만 extreme10 자체의 결과는 설계 시점에 보지 않았다.
- 지연과 토큰 수는 구독 환경이 보고한 값이고, 다른 트랙이 동시에 돌던 시간대에 쟀다. 공개 API 요금·속도와 같다는 보장은 없다.
- 금지 구문 검출은 정규식이라 난독화된 import 는 못 잡는다.
- 수리 피드백에 실패한 숨김 테스트 내용이 들어가므로 수리 후 통과율은 진짜 hold-out 기준보다 낙관적이다.
- 교차 수리에서는 다른 모델의 답을 수리 모델 자신의 이전 답인 것처럼 대화에 넣었다. 실제 코드 리뷰 상황과는 다르다.
